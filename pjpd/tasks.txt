Report out-of-order dependencies in `pjpd_list_tasks` output. Follow-up to dependson-n4en (the informational `Depends-On:` property), which must be built first.

Only dependencies with an equal or lower priority than the task that depends on them are reported. A dependency with a strictly higher priority is already planned to happen first, so priority takes care of it and there is nothing to say. Equal priority is reported because the order between two tasks of the same priority is ambiguous: the dependency is not clearly planned first (owner's decisions, 2026-11-14). What is reported is the case where priority does not guarantee the dependency comes first: the task could be picked up before something it waits on.

Rule: for each listed task, report the IDs in its `Depends-On` list that are (1) still in pjpd/tasks.txt (status ToDo) and (2) have a priority equal to or lower than the task's own. A dependency that is Done, Verified, removed or unknown is satisfied and never reported, so only tasks.txt needs to be read. Return them as a list property on the task (e.g. `blocked_by`), omitted when empty, so a calling model can see which tasks to do or reprioritize first.

Constraints: no reordering — list order stays priority-only, which is the owner's condition for having dependencies at all. Nothing is stored on disk; the report is computed at list time. No new tool (D-18). Cycles need no special handling.

Done when: list output reports an open dependency of equal priority and one of lower priority, does not report a strictly higher-priority one, and stops reporting once the dependency is marked done or reprioritized above the task; ONTOLOGY (tool interface, rule), RATIONALE (D-n), CRITERIA (rows plus tests under rust/tests/R-n/) and ARCHITECTURE_LOG are updated in the same change; `cargo test` in rust/ is green.
